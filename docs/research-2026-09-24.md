# Research & audit — 2026-09-24

Scope: an optimization pass on the OMP adapter, driven by three external sources plus a
redundancy audit of this monorepo. Everything below is either (a) verified against a live
artifact in this session, or (b) cited to a source with a file path. Unverified claims are
labelled.

## 1. Verified defects in the OMP adapter

These were found by reading the live host type definitions and a real session transcript.
They are bugs, not tuning: two of the three shipped hooks could never fire.

### 1.1 Verbatim compaction never activates

`packages/omp/src/compact.ts` matched only the Anthropic wire spellings
(`tool_use` / `tool_result`). OMP transcripts use different shapes:

- tool calls: a content block `{ type: "toolCall", id, name, arguments }`
- tool results: a separate message with `role: "toolResult"` plus `toolCallId` / `toolName` / `content`

Measured on a real 7.8 MB transcript: `toolCall` 720, role `toolResult` 720,
`tool_use` 0, `tool_result` 0. Consequently `flatten()` produced zero calls and
`planCompaction()` always deferred with `reason: "no-calls"`, spending no Jev calls.
The module and its tests were exercised only by fixtures written in the other spelling.

Latent companion bug: a flattened `toolResult` message left its text in `m.text` with
`m.toolResults` unset, so the result-body render branch could not run and the final
`parts.filter(Boolean).join("\n")` would have dropped a truncated result entirely
once the shape was fixed naively.

### 1.2 Skill router could never fire, twice over

`ExtensionContext` exposes no `skills` member. Verified against the live
`dist/types/extensibility/extensions/types.d.ts`: the 25 members are ui, mode,
getContextUsage, getAsyncJobSnapshot, compact, hasUI, cwd, sessionManager, modelRegistry,
localProtocolOptions, model, models, isIdle, abort, hasPendingMessages, shutdown,
isProjectTrusted, getSystemPrompt, runEphemeralTurn, memory, setInterval, setTimeout,
clearTimer, invokeTool — and the only occurrence of the word "skill" is inside the
`isProjectTrusted` doc comment.

Even with a roster, the return channel was wrong: `InputEventResult` is exactly
`{ handled?, text?, images? }`. `additionalContext` is declared only on
`SessionStopEventResult`.

### 1.3 The destructive gate could fail CLOSED

The in-handler try/catch is complete and tested for fast failures (missing key, 4xx,
budget exhaustion, malformed response). But the host maps a thrown or never-settling
`tool_call` handler to `{ block: true }` itself, with `toolCallTimeoutMs` defaulting to
30 000 ms. The handler passed no signal, and core's 3 attempts x 15 s plus quadratic
backoff can reach ~46 s. A slow upstream stall therefore blocked the tool instead of
allowing it. Fix: thread the host `AbortSignal` through and self-impose a deadline below
the host budget.

## 3. What OMP now provides natively

OMP core ships its own TypeSafe integration: a provider route to `/v1/systemone`, a
`TypeSafeJudge`, and `TYPESAFE_DEFAULT_MODEL = jev-latest`. The eval prelude exposes
`judge(state, questions)` and `judge_batch(states, questions)`, which take the same
typed `noul` / `choice` / `score` questions and return the same calibrated answers.
Verified working in this session with the existing `TYPESAFE_API_KEY`.

Consequence: the adapter's `jev_ask` and `jev_models` duplicated a native capability.
This is also why `TYPESAFE_API_KEY` remains a core credential even with no extension
installed — the help text names `eval judge()` as one of its consumers.

## 4. External sources

### 4.1 superterminal (sonnylazuardi/superterminal)

A GPU terminal emulator — not an LLM agent — but it ships a production Jev integration,
and that layer is the portable part. Cited files under `packages/app/src/ai/`:

- `palette-rank.ts:45-76` — one request carrying both a `choice` over candidate ids and a
  `noul` abstain gate; the abstain option is mandatory.
- `palette-rank.ts:104-138` with thresholds at `:33-37` — a two-regime merge into the
  local fuzzy list that never moves a cursor the user has already moved.
- `use-palette-ranking.ts:16,42-94` — 250 ms debounce, one request in flight, stale-answer
  discard, per-query cache.
- `jev.ts:61-69,118-148` + `service.ts:129-144` — a provider failure taxonomy mapped to a
  session policy (auth/model disable, rate_limit backs off honouring Retry-After, network
  stays silent).
- `screen-context.ts:143-162,178-202` — redaction with `looksRandom` / `looksLikePath`
  disambiguation so paths survive while bare hex and base64 do not.

### 4.2 madewithjev.com

A directory of projects built on Jev: 685 builds with a source link, of which 32 published
a cost and 15 a latency. The site files them under nine jobs; the dominant job by count is
"sort a pile too big to read" — the same questions over a large corpus, which is a
map-reduce shape. Only 12 of the builds are skills. Practical takeaway: the common real
workload is batch classification, not single-call judgment.

### 4.3 Orca (stablyai/orca)

An Agent Development Environment (Electron + pnpm, MIT). Findings worth noting, all cited
to the clone:

- `src/cli/command-suggestion.ts:14,41-42` — decides whether a mistyped token means a
  destructive verb with a Levenshtein test (`<= 1` edits). A hard-coded constant on a path
  whose errors are asymmetric and expensive; a calibrated judgment is the better shape.
- `src/main/ai-vault-search/session-search-query-planner.ts:20,45` — classifies a query as
  literal-by-shape with a nine-alternative regex, and records `truncated` so a degraded
  plan is announced rather than returned as a confident empty.
- `src/main/ai-vault-search/session-search-hit-ranking.ts:6,61` — a hand-tuned ranking
  prior (`0.02 * ln(1 + message_count)`), validated on two eval sets only.
- `src/main/automations/run-target-resolution.ts:22-32` — one fixed sentence per diagnosis,
  repeats coalesced on identical text, and the record still created so a refusal is
  debuggable rather than silent.
- `src/cli/agent-context.ts:28` — the entire CLI surface serialized as a versioned JSON
  schema, read from a static local registry with no runtime dependency.

## 5. What this pass implements

Driven by the above, and scoped by explicit user decision:

- core: a single `THRESHOLDS` object, `judgeDestructiveDual` (noul intent + choice with an
  abstain, satisfying three outcomes `allow` / `block` / `confirm`), a failure taxonomy,
  a refusal ledger, and a map-reduce batch helper.
- kit: the one shared env->config reader, actually adopted by the adapters.
- omp: the three defects above fixed, the tool surface reduced to what is not native,
  the approved patterns wired in, and the stale README claims corrected.
- eval: a dataset and harness so the dual gate's threshold is measured rather than guessed.
